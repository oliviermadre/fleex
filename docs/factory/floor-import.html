Export and import a floor

The floor goes out as a JSON file and comes back in, on this instance or another. What the file names and this instance does not have (a persona, a skill, a panel, a model, a board) is dropped on the way in. The machine is still placed, and it shows that it needs setting up, as a station freshly placed does.

Two buttons on the Build card

Slots 6 and 7 are free in build mode. Export downloads fleex-floor-2026-11-24.json at once. Import opens the file picker, then does what pick 1 says.

1 · Where the imported floor lands

A

It replaces the floor

You confirm first ("Replace the 84 machines of this floor?"). Undo brings the old floor back. Tickets on a machine that is gone fall on the floor, as with Erase.

B

It goes into your hand, like a paste

You place it where there is room, next to what is already there. Replacing a floor then means erasing it first.

C

It asks each time

recommended

A small modal: Replace the floor or Place it in hand. Restoring a backup and adding a line from someone else are both one click away. On an empty floor it skips the question and replaces.

3 · A station that is not set up, on the floor

This is the same mark as a station just placed with nothing chosen. Today only its popup says so, in red.

A

A dashed amber outline and a "!"

recommended

The mark is visible in build mode and out of it. The station is also listed top left with the tickets that wait for you, as "not set up", so N gets you there.

B

Greyed, with a "Set up" tag

It looks like a station switched off. That is quieter, but easy to mistake for one you stopped on purpose.

4 · What it does with tickets meanwhile

A

It takes them in and starts nothing

recommended

It behaves like a station switched off. Tickets wait in it with "Waiting: the station is not set up", and once you choose a persona it runs on them. It does not spend runs that are bound to fail.

B

As today: each run fails

Each ticket ends in "run failed" and has to be put back by hand once the station is set up.

The file, and the import, as understood

  • In the file: the machines, their names, settings and sizes, the areas, labels and decor. Intakes keep their source, rules, query and order. Script stations keep their lines.
  • Not in the file: tickets, items, runs, costs, an intake's last pull date, the floor's limits.
  • Things matched by name: personas, skills (command name), panels and models. A board is matched by its name, because its id differs from one instance to another. The file carries the names of the boards it uses.
  • What does not match is removed from the machine, never the machine itself. A desk keeps its type and priority and loses its board. An arm condition on a board loses that board; a condition left empty would let everything through, so the arm then takes nothing (and says so).
  • Ids are new, as with paste. Teleporters stay paired and arms keep their conditions.
  • A file from an older floor goes through the same upgrades as a stored floor (sizes as built, old filters read). A file from a newer Fleex is refused, with a message saying so.
  • Gmail intakes come in, and pull only once gog is set up on this instance, as today.
