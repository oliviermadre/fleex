GitHub entre par l'usine

Chaque notification GitHub qui te concerne (participating) devient un item. L'intake ne fait que dédoublonner : il agrège une rafale sur un même sujet (issue, PR), commente le ticket Fleex lié s'il existe, et relie un nouvel item à celui qui l'a précédé. Ce qui en devient un ticket, c'est le plancher qui le décide : un bras, puis une station agent avec le persona Fleex. Lecture seule sur GitHub : Fleex ne marque rien comme lu.

Les quatre cas

Choisis un cas, puis avance pas à pas. Le panneau de droite est la carte de l'item (ou le fil du ticket lié) à ce moment-là.

Ce que l'intake pose sur chaque item, en tags (lus par les bras) et en champs :

Et selon le cas : linked:yes + le ticket (#812), follow-up:yes + l'item qu'il suit.

La clé d'un item GitHub est le sujet plus le début de la rafale (evaneos/shop#355@10:02) : une même PR peut donner plusieurs items dans le temps, reliés. Le sujet seul sert à trouver le ticket lié et l'item précédent.

Sa rafale : l'item contient les commentaires arrivés pendant qu'il attendait sur le quai (auteur, heure, texte), lus par un appel par sujet mis à jour.

Ce qui est décidé

  1. Toute notification participating devient un item. Le watching est une option de l'intake, décochée.
  2. Rafale sur le quai : tant qu'un item du même sujet attend sur le quai, une nouvelle notification s'y ajoute et relance le délai de calme.
  3. Ticket lié (lien github_issue ou github_pr) : un commentaire sur le ticket à la sortie du quai, et l'item sort quand même, avec linked:yes.
  4. Item précédent déjà sorti (sur le plancher ou archivé) : un nouvel item follow-up:yes, relié ; l'ancien ne bouge pas, il est marqué « new activity ». Le brief de la suite dit où en est l'ancien et ce que les stations en ont dit.
  1. Devenir un ticket : un bras sur reason:review_requested ou reason:assign mène à une station agent, persona Fleex, qui crée ou retrouve le ticket par la CLI (fleex import <url>). Pas de station native tant que le concept n'est pas validé.
  2. Lecture seule sur GitHub. Les mails de GitHub : à exclure dans la query de l'intake Gmail, à ta main.
  3. Gmail ne change pas : un mail reste une conversation qui revient. Le modèle par rafale est celui de GitHub.
  4. Encore à prévoir : un ticket créé par l'agent n'arrive pas seul sur le plancher (la CLI n'a pas de commande factory) : il atterrit dans Inbound, ou on ajoute une commande pour le poser sur une machine.
