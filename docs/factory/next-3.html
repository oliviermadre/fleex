Le péage : un portique Set, une condition de rejet, un bras

Le péage est le portique Set avec une ligne de plus, « reject », et un bras rouge dessous. Il applique ses opérations, puis teste sa condition : si elle est vraie, le bras sort le ticket. Change la condition et le ticket, puis joue. La remise à zéro est un portique Set ordinaire, sur la sortie de la zone.

    Ce que ça implique

    • L'ordre : les opérations d'abord, la condition ensuite. Avec « passes +1 » puis « passes > 3 », le ticket fait trois tours et sort au quatrième ko.
    • La condition est celle des bras, avec en plus les tags clef:valeur comparés comme des nombres. Plusieurs conditions : il suffit qu'une soit vraie pour rejeter.
    • Le bras fait partie du péage : on choisit de quel côté il sort, et il se pose avec lui.

    Une question avant de construire

    • Un portique Set suivi d'un bras ordinaire à condition, posé contre la même case, ferait exactement la même chose : un bras prend déjà sur un convoyeur ce qui remplit sa condition. Le péage peut donc être un simple raccourci qui pose les deux d'un coup et les règle dans une seule popup, sans nouvelle machine dans le moteur. C'est ce que je propose, sauf si tu veux une machine à part.

    Le poste script : n'importe quelle commande, avec ou sans action par défaut

    Oui, tu as bien compris : la liste du poste ne contient que ce qui s'écarte de l'action par défaut. Et cette action est facultative : avec « none », le poste ne joue que ses propres lignes. Une ligne vise un dépôt, ou « any repository » pour une commande à jouer dans chaque worktree du ticket, quelle qu'elle soit (ouvrir un navigateur, prévenir quelqu'un, lancer un build).

    Ce que j'ai supposé

    • Une commande tourne dans le worktree du dépôt, avec le numéro et le titre du ticket en variables d'environnement.
    • Code retour 0 : réussi ; autre chose, ou délai dépassé : échec. La sortie de la commande est gardée sur le run du poste.
    • Pour chaque dépôt du ticket, dans l'ordre : sa ligne dans le poste, sinon la ligne « any repository », sinon l'action par défaut de la vue dépôt, sinon « pas de commande ».
    • Un ticket sans worktree n'a rien à jouer : je propose qu'il suive la règle « pas de commande ». Dis-moi si tu veux qu'une commande puisse tourner sans dépôt.
