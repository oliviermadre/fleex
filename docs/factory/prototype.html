Votre pipeline agentique, vu comme une usine

Chaque ticket est une pièce. Elle entre par un quai d’intake, passe au tri, puis descend la ligne de son workflow, poste après poste, jusqu’à l’expédition. Les chiffres de cette maquette sont simulés.

Quais d’intake
Gmail, Slack, Meeting notes, GitHub, Linear, Routines, CLI · MCP.
Pièces
Les tickets, colorés par type : build, fix, think, lead, ops.
Postes
Les étapes d’un workflow : agent, skill, panel ou native. Chaque case allumée est un run en cours.
Postes de contrôle
Les human_gate. La pièce reste sur l’étagère tant qu’un humain n’a pas tranché.
Convoyeurs ambre
Les boucles de reprise : un ko en QA ou un request_changes.
Slots agents
agentMaxConcurrency : la seule file d’attente côté agents, commune à toute l’usine.
Opérateur
Vous. Une seule personne pour toutes les gates, questions et erreurs, et seulement aux heures de bureau.
Drones
Les tickets créés par un workflow (ticket.create) qui repartent à l’intake.
  1. Goulots classe ce qui freine ou coûte le plus. Appliquez le premier réglage et regardez la ligne se vider.
  2. Focus liste ce qui vous attend. Approuvez une gate : la pièce repart tout de suite.
  3. Lancez Incident prod depuis le banc d’essai et observez les slots agents saturer.
